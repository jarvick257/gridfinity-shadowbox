# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Purpose

Python toolchain that turns a top-down photo of an object into a Gridfinity-ready
cutout STL. The repo is greenfield (empty at time of writing); this file records
the intended design so implementation stays consistent with it.

## Intended user workflow

1. Print the reference sheet (generated by this repo) with calibration markings.
2. Place the object on the sheet, photograph it straight down.
3. `step1`: image -> 2D outline SVG (edge detection, scale calibration, de-tilt).
4. `step2`: SVG -> extruded STL at a given height.

## Planned layout

```
gridfinity_cutter/
  sheet.py      # generate the printable reference sheet (PDF/SVG), known geometry
  step1.py      # photo -> outline SVG
  step2.py      # SVG -> STL
  cli.py        # entry points: gridfinity-cutter sheet|outline|extrude
tests/
```

Each step is a standalone CLI (`python -m gridfinity_cutter.step1 photo.jpg -o out.svg`)
so users can inspect and hand-edit the intermediate SVG before extruding.

## Environment and commands

Use `uv` (installed, Python 3.14 on this machine). Once `pyproject.toml` exists:

```
uv sync                          # create venv, install deps
uv run gridfinity-cutter sheet -o sheet.pdf
uv run gridfinity-cutter outline photo.jpg -o object.svg
uv run gridfinity-cutter extrude object.svg --height 20 -o object.stl
uv run pytest                    # all tests
uv run pytest tests/test_step1.py -k calibration   # single test
uv run ruff check . && uv run ruff format .
```

Planned dependencies: `opencv-python` (edge detection, marker detection,
perspective transform), `numpy`, `svgwrite` or `svgpathtools`, `shapely`
(contour cleanup), `trimesh` (extrude + STL export).

## Architecture notes

- **Reference sheet is the single source of truth for scale and tilt.** The sheet
  generator and step1 must share the same marker geometry (marker IDs, spacing in
  mm). Keep that in one module (`sheet.py`) and import it from step1; never
  hardcode marker spacing in two places. Prefer ArUco markers in the corners over
  a plain grid: they give unambiguous correspondences for the homography.
- **step1 pipeline order:** detect markers -> compute homography to sheet mm
  coordinates -> warp image (this removes tilt and fixes scale in one step) ->
  mask out marker regions -> edge/contour detection -> pick the largest contour
  not touching the sheet border -> simplify -> write SVG in mm units
  (`viewBox` in mm, 1 user unit = 1 mm) with the outline as a single closed path.
- **step2 must not care about images.** It only reads an SVG whose units are mm,
  optionally applies a clearance offset (buffer) and Gridfinity-related options
  (e.g. snap to 42 mm grid), and extrudes to STL. Keep it usable on hand-drawn SVGs.
- **SVG contract between steps:** mm units, one or more closed paths, no
  transforms. Document any deviation in both step modules.
- Real photos as test fixtures are large; keep a couple of small downscaled
  samples in `tests/fixtures/` and test geometry against known object dimensions
  with tolerances rather than exact pixel matches.
